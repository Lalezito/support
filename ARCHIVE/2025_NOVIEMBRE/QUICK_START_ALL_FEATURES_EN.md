## 2. BACKEND DEPLOYMENT (10 minutes)

### Step 2.1: Deploy to Railway (3 minutes)

1. **Create New Project**
   ```bash
   # Login to Railway.app
   # Click "New Project"
   # Select "Deploy from GitHub repo"
   # Choose: flutter-horoscope-backend
   ```

2. **Add PostgreSQL**
   ```
   Click "Add Service"
   → Select "PostgreSQL"
   → Wait for provisioning (~60 seconds)
   ```

3. **Add Redis**
   ```
   Click "Add Service"
   → Select "Redis"
   → Wait for provisioning (~30 seconds)
   ```

### Step 2.2: Configure Environment Variables (2 minutes)

In Railway project settings, add:

```bash
# Database (auto-generated by Railway)
DATABASE_URL=${{Postgres.DATABASE_URL}}

# Redis (auto-generated by Railway)
REDIS_URL=${{Redis.REDIS_URL}}

# OpenAI
OPENAI_API_KEY=sk-your-key-here

# JWT Secret (generate random 64-character string)
JWT_SECRET=your-random-64-char-string-here

# Node Environment
NODE_ENV=production

# Port (Railway auto-assigns)
PORT=3000

# CORS (your frontend domains)
ALLOWED_ORIGINS=https://your-app.com,capacitor://localhost
```

### Step 2.3: Deploy Backend (5 minutes)

```bash
cd /Users/alejandrocaceres/Desktop/appstore.zodia/backend/flutter-horoscope-backend
```

## TROUBLESHOOTING

### Backend Issues

**Problem:** Health endpoint returns 500
```bash
# Check Railway logs
railway logs

# Common causes:
# - DATABASE_URL not set
# - Redis not connected
# - OpenAI API key invalid

# Verify environment variables
railway variables
```

**Problem:** Database connection fails
```bash
# Test connection manually
psql $DATABASE_URL -c "SELECT NOW();"

# If fails, check:
# - DATABASE_URL format correct
# - Network access allowed
# - Database service running in Railway
```

**Problem:** OpenAI API errors
```bash
# Test API key
curl https://api.openai.com/v1/models \
  -H "Authorization: Bearer sk-your-key"

# If fails:
# - Check API key valid
# - Check billing enabled
# - Check rate limits not exceeded
```

### Frontend Issues

**Problem:** API calls failing (network error)
```dart
// Check API base URL matches Railway deployment
// File: lib/config/api_config.dart

// Should be:
static const String baseUrl = 'https://your-app.up.railway.app';

// NOT:
// static const String baseUrl = 'http://localhost:3000'; // ❌
```

**Problem:** Translations missing
```bash
# Regenerate localizations
cd zodiac_app
flutter gen-l10n

# Verify ARB files exist
ls -la assets/l10n/
# Should see: app_en.arb, app_es.arb, etc.
```

**Problem:** RevenueCat purchases fail
```bash
# Check:
□ API keys match platform (iOS vs Android)
□ Product IDs match App Store Connect
□ Sandbox account logged in (iOS Settings)
□ Test mode enabled in RevenueCat dashboard
```

### Database Issues

**Problem:** Migrations fail
```bash
# Check existing tables
psql $DATABASE_URL -c "\dt"

# Drop and recreate if needed (CAUTION: dev only!)
# psql $DATABASE_URL -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"

# Re-run migrations
# psql $DATABASE_URL -f migrations/001_*.sql
```

**Problem:** Slow queries
```bash
# Check indexes exist
psql $DATABASE_URL -c "\di"

# Analyze query performance
psql $DATABASE_URL
# EXPLAIN ANALYZE SELECT * FROM chat_messages WHERE user_id = '...';
```

### Performance Issues

**Problem:** Slow API responses (>3 seconds)
```bash
# Check Railway metrics
# → Click on service
# → Metrics tab
# → Check CPU/Memory usage

# If high:
# - Scale up Railway plan
# - Optimize database queries
# - Increase connection pool
# - Add more Redis caching
```

**Problem:** High memory usage
```bash
# Check for memory leaks
# Run app with --profile flag
flutter run --profile

# Use DevTools memory profiler
# Look for growing heap

# Common causes:
# - Listeners not disposed
# - Large images not cached
# - Stream subscriptions not cancelled
```

## COMMON ERRORS & SOLUTIONS

### Error: "Daily limit exceeded"
**Solution:** This is normal behavior for free users after 5 messages. Test with premium account or wait 24 hours.

### Error: "Invalid session"
**Solution:** Session expired. Clear app data and login again.

### Error: "OpenAI API rate limit"
**Solution:** Implement request queuing or upgrade OpenAI tier.

### Error: "Database connection pool exhausted"
**Solution:** Increase `max_connections` in Railway PostgreSQL settings.

### Error: "Translation key not found"
**Solution:** Run `flutter gen-l10n` and rebuild app.

### Backend Optimizations

```javascript
// Enable compression
app.use(compression());

// Set proper cache headers
res.setHeader('Cache-Control', 'public, max-age=3600');
```

### Frontend Optimizations

```dart
// Cache images
CachedNetworkImage(
  imageUrl: url,
  memCacheWidth: 400,
  memCacheHeight: 400,
);

// Lazy load lists
ListView.builder(
  itemBuilder: (context, index) => item,
  cacheExtent: 100.0,
);

// Debounce API calls
Timer? _debounce;
void onSearchChanged(String query) {
  if (_debounce?.isActive ?? false) _debounce!.cancel();
  _debounce = Timer(const Duration(milliseconds: 500), () {
    performSearch(query);
  });
}
```

### Database Monitoring

```sql
-- Check slow queries
SELECT query, mean_exec_time, calls
FROM pg_stat_statements
ORDER BY mean_exec_time DESC
LIMIT 10;

-- Check table sizes
SELECT
  schemaname,
  tablename,
  pg_size_pretty(pg_total_relation_size(schemaname||'.'||tablename)) AS size
FROM pg_tables
WHERE schemaname = 'public'
ORDER BY pg_total_relation_size(schemaname||'.'||tablename) DESC;
```
